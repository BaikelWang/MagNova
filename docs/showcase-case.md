# 从研究想法到探索候选

这个案例展示 MagNova 如何把科研讨论逐步转化为有明确参数、用户确认与产物溯源的材料任务。它的价值在于让需求、文献、结构和解释对应起来，而不是用一张结构图宣称已经发现新材料。

## 一个任务，六个阶段

1. **研究讨论。** 用户提出磁性半导体研究方向，系统说明可提供的帮助与验证边界，不启动计算。
2. **文献检索。** 检索相关方法，展示论文出处、PDF 页码与原文摘录。文献是方法依据，不是新候选的验证结果。
3. **需求澄清。** 将目标细化为不含稀土元素、目标带隙严格大于 0.2 eV，核对数值、单位和比较关系。
4. **参数确认。** 展示结构化需求，保留严格 `>`；确认之后才允许提交科学任务。
5. **候选生成。** 运行材料生成、结构治理、弛豫、代理预测与筛选，返回同任务候选、3D 结构及 CIF。
6. **结果分析。** 依据当前候选的原始字段，解释排序、风险及尚未证明的要求，不重新编造数值。

![从文献与需求形成到明确参数](assets/requirement-confirmation.png)

归档展示包含 **25 条消息：12 条用户消息与 13 条助手消息**。这些记录选自同一科学任务，并包含界面修复后的分段恢复。它是可追溯的案例选录，不是未剪辑、从不中断的一次全自动会话。

## 阶段数量

该任务的产物汇总记录为：

- 生成结构 **40** 个。
- 预筛通过 **35** 个，未通过 **5** 个。
- 弛豫成功／进入预测 **34** 个；弛豫失败或跳过合计 **6** 个。
- 任务记录报告唯一候选 **34** 个、重复计数 **1**。
- 默认返回展示 **10** 个候选。
- 队列记录为 **34 个 exploration、0 个 exploitation、6 个 rejected**。

这些是同任务不同阶段的汇总口径，不能相加成新样本总量，也不能把默认展示的 10 个候选当作全部通过科学验证的材料。归档中的逐候选筛选原因与部分治理溯源尚不完整，因此保留 `partial_provenance` 标记，不额外推演每一步淘汰的完整因果。

## FeO 候选：结构与预测分别说明

![FeO 探索候选的结构、代理预测与下载](assets/crystal-results.png)

展示候选为 **`g1_gen_020`（FeO）**，属于 `exploration` 队列。其弛豫结构记录包含：

- `p_is_stable_relaxed`：**0.377**，稳定性代理概率。
- `p_bandgap_gt02_relaxed`：**0.932**，带隙大于 0.2 eV 的代理概率，**不是 0.932 eV 的带隙测量值**。
- `p_reported_is_fm_relaxed`：**0.985**，reported-FM 标签的代理概率，不能据此证明磁性基态。

页面显示值在此保留三位小数；[脱敏案例汇总](evidence/showcase-case.json)保留原记录中的数值文本。Top1 表示当次 Agent 排序位置，不表示它已满足所有目标，也不表示 FeO 这一化学式本身是新发现。

对应 CIF 的 SHA256 为：

```text
77fcc36f0e910eab66818e11f29c3b3ad28722d733e7026ca86211511eba9a1e
```

公开入口的下载检查核对了该哈希，确认所展示结构与下载产物一致。完整 CIF 集合和私有后端产物不随本仓库分发。

## 科学结论到哪里为止

本案例完成了真实任务执行与展示，但没有提供可核验的 DFT 或实验结论。生成条件、代理预测、排序位置与科学验证是四件不同的事。后续需要独立计算或实验，核查结构稳定性、目标性质、磁序及可合成性。

![基于原记录说明风险与后续验证](assets/result-analysis.png)

本地 Mock 示例用于复现接口与工程流程，不能替代这一历史真实任务，也不能作为材料性质证据。文献及图片署名见[素材说明](assets/README.md)；模型与系统验收口径见[验证说明](validation.md)。
