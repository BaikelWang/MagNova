# 验证说明

MagNova 的展示涉及三个不同对象：竞赛部署系统、当前公开工程基线，以及历史模型实验。它们的输入、依赖和评分方式不同，结果分别记录，不合并成一个“准确率”。

## 竞赛部署系统的归档验收

2026 年 10 月 22 日的冻结版本记录了：

- 工程回归共 **1183 项**：**1182 项通过、1 项跳过**，零失败、零报错。
- **10 项会话浏览器检查通过**：登录、普通交流、真实检索、刷新恢复、同账号第二窗口、旧窗口冲突、明确重新同步、删除、已删除记录不复活，以及旧计算确认授权不恢复。
- 公开入口另外核对了登录、文献检索、历史案例、3D 交互、CIF 下载与退出；下载结构的哈希与案例一致。

这轮验收没有重新训练模型、调用付费 API 或启动新的材料计算。任务状态观察与故障处理还使用了 CPU 模拟控制；不能把模拟故障检查称为重新完成了一次真实科学任务。

当次切换控制器曾报告启动身份校验异常。后续核对确认冻结候选已经运行，并完成公开入口检查，原失败记录与独立对账记录均保留；并未删除失败来拼成“所有尝试均成功”。这也不是七天稳定性观察完成的证明。

上述数字描述**当时完整部署的工程行为**，不代表模型答对率、科学任务成功率，也不代表现在克隆仓库会运行相同数量的测试。[脱敏归档摘要](evidence/archived-validation.json)保留计数、范围与源文件指纹，不包含原始内部回执。

## 当前公开代码与 CI

本次 GitHub 更新保留历史公开工程基线，仅新增精选展示与说明。完整竞赛部署、最新 Harness 实现、模型权重和私有数据没有整体发布；不能把产品截图视为此仓库代码可直接复现的完整页面。

公开 CI 在 Python 3.10 与 3.12 上安装本仓库的开发依赖并运行 `pytest`。它验证公开代码、契约和可复现的 Mock／CPU 路径，不加载私有科学模型，不执行付费调用，也不证明真实材料性质正确。

**当前提交的状态以 [GitHub Actions](https://github.com/BaikelWang/MagNova/actions/workflows/ci.yml) 为准。** 历史部署的 1182 个通过项不会自动计入公开 CI。依赖、许可证与另行获取资产的要求见[公开范围](public-release-scope.md)和 [NOTICE](../NOTICE.md)。

## 历史 V5.3 模型记录

[`reports/v52b_v53_hidden5_summary.json`](../reports/v52b_v53_hidden5_summary.json)保留早期需求解析实验的聚合结果，不包含题目与答案。文件名中的 `hidden5` 是历史实验名称，不单凭名称宣称数据从未被消费。

以 V5.3 的三个分组为例，每组各 300 条：

- **ID 分组**：JSON 与 Schema 有效率均为 100%；raw model 的完整契约精确率为 **13.33%**，当时 pipeline 为 **12.00%**。
- **OOD 分组**：JSON 与 Schema 有效率均为 100%；raw model 的完整契约精确率为 **10.67%**，当时 pipeline 为 **0%**。
- **对抗分组**：JSON 与 Schema 有效率均为 **99.67%**；raw model 的完整契约精确率为 **21.33%**，当时 pipeline 为 **0%**。

这些结果说明“能生成合法 JSON”不等于“完整理解了需求”。`raw_model` 与 `current_pipeline` 是不同评估对象；pipeline 字段表示该历史实验中的处理链路，不是今天线上系统的别名。三个分组也不混成一个总分。

该摘要没有给出足以独立复现性能压测的完整硬件、输入长度、并发和测量条件，因此不把其中的 batch 耗时改写为当前服务的首字延迟或吞吐。历史模型成绩与 10 月 22 日应用验收，更不能互相抵扣。

## 科学案例的边界

展示案例的阶段数量与结构产物来自同一任务，但属于 `exploration`，逐候选治理溯源仍标为 `partial_provenance`。没有可核验的 DFT／实验结论，就不将候选预测称为已验证物性。[同任务案例与字段解释 →](showcase-case.md)

因此，本仓库展示的是可检查的系统成果与工程研究记录，而不是“每个模型实验都成功”“所有候选都符合目标”或“新模型已经全面超越旧生产基线”的声明。
